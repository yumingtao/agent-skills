# 信号规则

四类信号都可以单独开一条维护：TRACE 对照、评测评语、复盘复发、结构检查。不要求先有复盘日志。安全评语是评测评语的一种，优先级最高。

| 顺序 | 信号 | 成立条件 |
|---|---|---|
| 1 | 安全评语点名 | 平台报告点了某一句。只采用那一句，不把实验室规则写进技能 |
| 2 | 评测评语 | 某一版评语点名一个现象，并能对上一个 TRACE 子项 |
| 3 | 复盘复发 | `metrics/workflow-feedback.jsonl` 里，同一技能、同一缺口再次出现 |
| 4 | TRACE 对照 | 「按 TRACE 过一遍」时，某一子项在评分档里还不能稳定使用。怎样算稳定使用，以 [`trace-items.md`](trace-items.md) 为准 |
| 5 | 结构检查 | 中英文 `version` 不一致、`tags` 数量不一致，或英文安装树缺少 README 点名的脚本 |

一次只提案排序最前的那一条。其余写进「本次不改」。

## 外部材料最低字段

- 复盘日志一行：至少有技能名和缺口。缺字段时只问一次，不开始对照（SM-E14）。
- 贴来的评测报告：至少有子项名和该子项分数。缺字段时只问一次，不开始对照（SM-E14）。
- 接口可读时，用接口里的子项分；接口不可用时用贴来的报告，并在提案里写明（SM-E08）。

## 少见组合（唯一结论）

- 两种或更多信号同时在：按上表优先级只留第一条，其余写入「本次不改」（SM-E03）。
- 目标里只有这条缺口所要文字的一部分：仍算缺口，补齐缺的那一段。不要因为有半句就跳过（SM-E17）。
- 只改引用文件、行为段落不变：版本行写「不升版本」。
- 本地对照档到了 5 分档、平台同一子项仍是更低分：听平台分。文档对照只作缺口候选，不覆盖平台分。

## 自动补到阈值

只在调用里出现「自动补到阈值」时进入。每一轮仍只改一条，写完再比一次。

- 阈值是每个可评子项的最低分，默认 `4.8`，可改为 `(0, 5.0]` 内的其他数。不用五维平均。给出的数不在这个范围内时，不开始循环，只问一次（SM-E13）。不把越界的数改成默认值。
- `trust.scan` 不进入循环。
- **怎样得到用来比较的分数（折算）**：
  1. 该子项已有平台分数（接口或贴来的报告）→ 用该分数和阈值比。本地档位不覆盖它。
  2. 没有平台分数 → 正文达到该子项 5 分档记 `5.0`；只达到 4 分档记 `4.0`；更低档按档位整数记为 `N.0`。
  3. 必须有一次真实运行才能升的子项 → 保持现有比较分，不进「已达到」，也不在循环里改写成达标。
- 本地自测结论写两行：文档对照档位；是否有真实运行证据。没有第二行，不宣称已经达到阈值。
- 只挑选靠改文档能提高的子项，例如补用例、补恢复步骤、补错误码。
- 停机：可评子项的比较分都达到阈值；剩下的低分都要真实运行；或已经 5 轮。
- 停下时列出未达标子项和原因（SM-E09）。

## 任意目录

目录里有 `SKILL.md` 就可以维护。这是主路径。

本仓库的同步是可选步骤，只在目标位于 `skills/<name>/` 且脚本就在旁边时运行：

- `sync/check.sh --collection-only`
- `dsh-plugin/sync.sh`，不带 `--publish`

脚本不存在，或目标在别的目录，就跳过，并在「本次不改」里写明没有跑仓库同步。
