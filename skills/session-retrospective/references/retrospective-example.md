# 回顾示例

一个真实会话的完整回顾记录。日常回顾按 SKILL.md 的规则执行即可；不确定记不记、怎么合并时再读本文。

## 场景

一场 skill 质量提升会话：工程师让 agent 对新 skill 做质量审查、对比竞品、融入优化。会话结束时调用本技能。

## 提取的条目

回顾对话后，识别出三个工作流问题 + 一个成功信号：

**条目 1 — 表述夸大被纠正：**

```json
{"timestamp": "2026-11-13T15:30:00+08:00", "platform": "trae", "area": "review", "result": "corrected", "issue_type": "other", "priority": "medium", "notes": "agent 声称'已完成自测'但只跑了结构检查，无内容级测试；正确行为：区分'结构校验'与'自测'，未做的不说已做"}
```

要点：追问下发现所谓"自测"只是 `check.sh` 的结构校验——这是**需纠正的错误答案**（铁律 1：指向真实轮次）。notes 一句话问题 + 一句话正确行为，未超 200 字符。

**条目 2 — 同类问题合并 + 复发标注：**

会话中发现两处文档缺口：步骤 3 跳过条件缺环境类场景、跨技能相对链接在独立安装时断链。两者本质是同一个规则缺口——**skill 文档缺少"独立安装视角"审查**。合并为一条：

```json
{"timestamp": "2026-11-13T15:31:00+08:00", "platform": "trae", "area": "docs", "result": "failed", "issue_type": "other", "priority": "medium", "notes": "两个 skill 文档缺口同因：写文档未考虑独立安装场景（跳过分支不全、相对链接断链）recurring(第2次)；建议加入 skill 完成检查清单"}
```

要点：两轮发现合并为一条（反模式 5）；如果历史日志已有 `area=docs` 的同类条目，还要标注 `recurring(第N次)` 并把 priority 提到至少 medium——这正是复发的价值：单次是偶发，两次以上就是规则缺口。

**条目 3 — 成功信号：**

```json
{"timestamp": "2026-11-13T15:32:00+08:00", "platform": "trae", "area": "review", "result": "success", "issue_type": "none", "priority": "low", "notes": "真实 Jira 只读冒烟测试走通全流程，暴露的文档缺口当轮修复，闭环有效"}
```

## 不记录的（示例）

- 工程师中途补充了一句"先不推送代码"——这是正常澄清，无修复目标，不记。
- 工程师说"好的思路"——夸奖不记。
- Jira 搜索返回了无关工单——工具行为符合预期（无匹配 ≠ 错误），不记。

## 汇总表

| 区域 | 问题类型 | 优先级 | 备注 |
|------|---------|--------|------|
| review | other | medium | 表述夸大（自测） |
| docs | other | medium | 独立安装视角缺口 recurring(第2次) |
| review | none | low | 冒烟测试闭环成功（success） |

## 文件更新建议

- 各 skill 的完成检查清单模板 → 考虑加"独立安装视角"检查项
- skill 创作工作流的验证阶段 → 区分结构校验/内容自测/功能冒烟三层
