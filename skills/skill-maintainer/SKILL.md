# 技能维护

这只技能修改已经存在的技能，不负责打分。本技能用附带的评分档找出一处缺口，写出提案，确认后才改文件。

本技能的版本是 `1.0.4`。提案里的版本行属于**被维护的那只技能**，不是本技能。

## 铁律

1. **自检只用附带的评分档。** 档位在 [`references/trace-items.md`](references/trace-items.md)。`trust.scan` 不评、不打分。技能正文不收录科恩实验室或云鼎实验室的检测规则。
2. **没有信号不改规则。** 信号只来自 TRACE 对照、评测评语、复盘复发、结构检查。对不上 15 个子项、也不是仓库不变量的条目，暂缓。
3. **一次一条。** 其余缺口写入「本次不改」。
4. **默认确认前不写入。** 行为有变化时，目标技能的中英文 `version` 一起升一个补丁。只改 README 导航时不升该技能的版本。只有「自动补到阈值」才连续写入，并且仍是一轮一条。

## 何时使用

- 「维护这个技能」「按 TRACE 过一遍」「按评测改技能」「自动补到阈值」「skill maintainer」
- 手里有一份评测评语、一条复盘，或一次中英文不一致
- 示例：「维护 example-skill，先给提案。」确认前不改文件。对方回复「确认」后，只改提案里的那一处。

## 何时不用

- 从零设计一只新技能 → `workflow-skill-designer`
- 把本次会话记入日志 → `session-retrospective`
- 要求在本地重做安全扫描 → 停下，说明 `trust.scan` 不在本技能范围内（SM-E05）

## 流程

1. **确定目标技能。** 没说清就只问一个问题：改哪一只。任何含 `SKILL.md` 的目录都可以，不要求它在本仓库里。
2. **读取信号。** 按入口读取，不要等四类信号齐全：
   - 「按 TRACE 过一遍」：用评分档读 `SKILL.md` 与它点名的引用。某一子项还不能稳定使用，即构成缺口。怎样算稳定使用，以评分档文件的说明为准。
   - 评测评语或评测接口结果：把点名的句子对上一个子项。接口读不到时用贴来的报告，并在提案里写明（SM-E08）。
   - 复盘日志：默认 `metrics/workflow-feedback.jsonl`。只采用同一技能、同一缺口的复发项。
   - 结构检查：中英文 `version`、`tags` 数量、英文安装树是否含有 README 点名的脚本。
3. **只留一条。** 优先级：安全评语点名的项 → 评测评语 → 复盘复发 → TRACE 对照 → 结构偏差。安全评语只使用对方点名的那一句，不据此补写实验室规则。
4. **写出提案后停下。** 模板见 [`references/proposal-template.md`](references/proposal-template.md)。
5. **确认后才写入。** 中英文对应段落一起改。主路径到此结束。只有目标位于本仓库的 `skills/<name>/`，并且脚本就在旁边时，才可选地运行 `sync/check.sh --collection-only`；若同时存在 `dsh-plugin/sync.sh`，再运行它，不带 `--publish`。脚本不存在，或目标在别的目录，就跳过，并在「本次不改」里写明。脚本失败时按报错修一次再跑；第二次仍失败就停下并报告，不把失败记成通过。不发布到 SkillHub，不执行 `npm publish`。

信号优先级、阈值循环与暂缓条件在 [`references/signal-rules.md`](references/signal-rules.md)。

## 自动补到阈值

入口是「自动补到阈值」。没有这句时，仍走上面的提案和确认。

- 一轮只改一个靠改文档能提高的子项，中英文一起改，然后用同一份评分档再看。
- `trust.scan` 不参与。
- 阈值、可接受的范围和停机条件写在 [`references/signal-rules.md`](references/signal-rules.md)。不在这里重复数字。
- 停下时列出仍未达到的子项和原因。不把未运行写成已经验证（SM-E09）。

## 仓库不变量

缺口也可以落在这些格子上，而不落在某个 TRACE 子项上：

- 中英文同一补丁：改了 `SKILL.md` 的行为，就要改 `SKILL.en.md` 的对应行为，版本号同时移动
- 单一事实源：平台副本从 `skills/<name>/` 同步，不手改副本
- 只读技能不写：目标技能若声明只读，维护不给它增加写操作
- 日志不记秘密

## 异常

| 码 | 场景 | 处理 |
|---|---|---|
| SM-E01 | 没指定目标技能 | 只问一个问题，不开始对照 |
| SM-E02 | 缺口对不上 15 个子项，也不是仓库不变量 | 记为暂缓，不写入 |
| SM-E03 | 一次塞进多条缺口 | 按优先级留下第一条，其余写入「本次不改」 |
| SM-E04 | 只改了中文 | 停下，先补英文对应段落和版本号 |
| SM-E05 | 要求在本地做安全扫描 | 说明 `trust.scan` 不评；不编造扫描分 |
| SM-E06 | 其实是要一只新技能 | 交给 `workflow-skill-designer` |
| SM-E07 | 其实是要记这次会话 | 交给 `session-retrospective` |
| SM-E08 | 评测接口不可用 | 改用贴来的报告；提案里写明接口没读。不重试扫描 |
| SM-E09 | 阈值循环停下仍有低分子项 | 列出子项和原因，结束。不把它们改成达标 |

## 目标技能的版本

提案中的版本属于目标技能。行为变化：中英文 frontmatter 的补丁号一起加一。只改 README 导航：写「不升版本」。次版本或主版本只在确认时另行指定。

本技能自己的 `version` 保持当前值，除非这次维护的目标就是 `skill-maintainer`。

## 常见问题

**问：阈值看各项的平均吗？**
答：不看。每个可评子项各自和阈值比。数字在 [`references/signal-rules.md`](references/signal-rules.md)。

**问：循环会不会一直改下去？**
答：不会。达到 signal-rules 里的停机条件就停下，并列出还没达到的子项。

**问：没说「自动补到阈值」也会直接改文件吗？**
答：不会。那个入口才会连续写入。其他入口先给提案。

**问：这只技能负责打分吗？**
答：不负责。本技能只修改，不给出分数。
