# 信号规则

四类信号都可以单独开一条维护：TRACE 对照、评测评语、复盘复发、结构检查。不要求先有复盘日志。安全评语是评测评语的一种，优先级最高。

| 顺序 | 信号 | 成立条件 |
|---|---|---|
| 1 | 安全评语点名 | 平台报告点了某一句。只采用那一句，不把实验室规则写进技能 |
| 2 | 评测评语 | 某一版评语点名一个现象，并能对上一个 TRACE 子项 |
| 3 | 复盘复发 | `metrics/workflow-feedback.jsonl` 里，同一技能、同一缺口再次出现 |
| 4 | TRACE 对照 | 「按 TRACE 过一遍」时，某一子项低于 4 分档 |
| 5 | 结构检查 | 中英文 `version` 不一致、`tags` 数量不一致，或英文安装树缺少 README 点名的脚本 |

一次只提案排序最前的那一条。其余写进「本次不改」。

## 自动补到阈值

只在调用里出现「自动补到阈值」时进入。每一轮仍只改一条，写完用同一份评分档重打。

- 阈值是每个可评子项的最低分，默认 `4.8`，可改为 `(0, 5.0]` 内的其他数。不用五维平均。
- `trust.scan` 不进入循环。
- 只挑选靠改文档能提高的子项，例如补用例、补恢复步骤、补错误码。必须有一次真实运行才能升的子项，不在循环里改写成达标。
- 停机：可评子项都达到阈值；剩下的低分都要真实运行；或已经 5 轮。
- 停下时列出未达标子项和原因（SM-E09）。

## 暂缓

- 只出现在第三方 TRACE 清单里、对不上这 15 个子项的条目
- 低于 4 分档，但本次入口不是「按 TRACE 过一遍」，也没有评语或复盘点名
- 要求在本地补做 `trust.scan`

## 目标不在 skills/ 下

目录里有 `SKILL.md` 就可以维护，包括 `tmp/` 和仓库之外。

- 不运行 `dsh-plugin/sync.sh`。它只刷新集合里已发布的包，不检查这个目标。
- 没有改到 `skills/`、`skills-en/`、README 或 `dsh-plugin/` 时，不运行 `sync/check.sh`。
- 在提案的「本次不改」里写明没有跑仓库同步。
