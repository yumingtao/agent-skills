# 提案模板

默认确认前只输出这段，不改文件。「自动补到阈值」除外：那一入口一轮写一条。版本行属于目标技能。本技能自己的版本不写在这一行，除非目标就是 `skill-maintainer`。

```text
目标技能：
缺口：
信号来源：TRACE 对照 | 评测评语 | 复盘 | 结构检查
对应子项：例如 convention.docQuality；结构问题写「中英文同一补丁」
自检依据：该子项的哪一档没有达到
本次改动：
本次不改：
版本：目标技能 x.y.z → x.y.(z+1)，中英文同时；或「不升版本」
确认前不写入。
```

## 填好的例子

目标是 `clarify-before-acting`，评语写「中英文版本不一致」。这只改版本号对齐，不改行为段落。

```text
目标技能：clarify-before-acting
缺口：英文 frontmatter 的 version 落后于中文
信号来源：结构检查
对应子项：中英文同一补丁
自检依据：仓库不变量要求行为与版本一起移动；此处行为已对齐，只差版本号
本次改动：SKILL.en.md 的 version 改为与 SKILL.md 相同
本次不改：评分档里其他低于 4 分、但没有被点名的子项
版本：目标技能的英文改为与中文相同的补丁号；不因为这次对齐再加一
确认前不写入。
```

复盘复发。日志里同一技能两次把只读流程写成了会改文件。

```text
目标技能：example-skill

信号来源：复盘
对应子项：仓库不变量「只读技能不写」

本次改动：在流程里写明只读步骤禁止创建、修改和提交文件，并加一条对应异常码
本次不改：未在日志里复发的其他子项
版本：1.2.1 → 1.2.2，中英文同时
确认前不写入。
```

## 已经跑过的一次

目标是临时技能 `note-stub`，目录在 `tmp/skill-maintainer-fixture/note-stub/`。确认前没有改文件。确认后只把英文 `version` 从 `1.0.0` 改成 `1.0.1`。当时按旧规则跑了 `dsh-plugin/sync.sh`，它只刷新了集合里的包，没有检查 `note-stub`。从 `1.0.2` 起，目标不在 `skills/` 下时不再跑这一步。

```text
目标技能：note-stub
缺口：英文 frontmatter 的 version 落后于中文
信号来源：结构检查
对应子项：中英文同一补丁

本次改动：SKILL.en.md 的 version 改为 1.0.1
本次不改：没有被点名的反模式和用例缺口。目标在 tmp/，不登记进 README，不发布
版本：英文改为与中文相同的 1.0.1；不因为这次对齐再加一
确认前不写入。
```

那一次确认后的结果：两边 `version` 都是 `1.0.1`，行为段落未改。后来补反模式、常见问题和用例时，中英文一起升到 `1.0.2`。
