# 公开推送清单

先完成 `SKILL.md` 里的远端和范围，再逐项填写。每一项都要有结果。

结果只有六种：

| 结果 | 含义 |
|---|---|
| 通过 | 这一项在本次范围内没有问题 |
| 失败 | 这一项挡住推送 |
| 不适用 | 仓库没有这一项所依赖的文件，或本次范围内没有这类变更 |
| 未读 | 二进制或无法读取的文件，不能当成通过 |
| 跳过 | 远端不是公开仓库，整份公开清单不跑 |
| 未确认 | 公开性查不清。挡住推送 |

用户要求推送时，只有每一项都是通过或不适用，才可以推。未读、失败、未确认都停止。跳过只用于已确认的非公开远端。

## 项

### PP-01 远端公开性

- 通过：有证据表明远端是公开仓库，或有证据表明它不是公开仓库。不是公开仓库时，PP-02 至 PP-09 全部记为跳过。
- 未确认：查不到可见性。不把未确认写成通过。
- 报告：远端地址、公开或非公开。不根据仓库名称猜测。

### PP-02 敏感信息

只看本次范围：范围内的提交差异，以及同一句话要求提交时的暂存区和工作区。

算敏感信息的类型：私钥、API 令牌、Bearer 凭据、口令赋值、云厂商凭据、带口令的连接串、含秘密的环境变量文件。

- 通过：范围内没有这些类型。
- 失败：写出路径和类型。不写出秘密正文，不写出前后若干字符。
- 秘密已经在远端：父提交已被远端包含时，记为失败，说明「已在远端」，并停止。不用新提交假装消除，不改写历史。从即将推送、尚未到达远端的提交里去掉该文件，才谈得上下一次检查。本技能不代做历史改写。

### PP-03 邮箱与作者身份

作者只能是允许名单中的那个人。对照这些身份字段，不对照提交说明正文里顺带提到的产品名：

- 每个提交的作者名、作者邮箱、提交者名、提交者邮箱
- 提交说明里表示作者身份的尾注，包括 `Co-authored-by`、`Signed-off-by`，以及其他把人或代理写成作者、签名者或生成者的尾注
- 差异新增行里的邮箱

含 noreply 的托管平台地址也算作者身份。

允许名单：

- 仓库有 `sync/manifest.sh` 时，只读其中的 `SYNC_ALLOWED_EMAILS`。这份名单代表仓库所有者本人。
- 没有该文件时，只读仓库里已经声明的允许名单。没有声明，这一项失败，只问一次名单放在哪里。
- 不编造公司域名清单，不把地址抄进报告或技能正文。

AI 作者：身份字段里的名称或地址指向编码代理、聊天模型或机器人，而不是允许名单中的人。名称是 Cursor、Claude、Copilot、ChatGPT、Codex、Gemini、Devin，或者以代理、机器人自居时，记为 AI 作者。这种身份写进允许名单也仍然失败。只在提交标题或正文里提到这些产品名，不算 AI 作者。

- 通过：每一处人名和邮箱都属于允许名单中的那个人，并且没有任何 AI 作者。
- 失败：写出提交或文件路径，以及字段名（作者、提交者、尾注、正文）。AI 作者的说明写「AI 作者」。不写出邮箱地址，也不写出代理的地址。

### PP-04 README

用户可见的变更包括：命令、安装方式、对外行为、公开接口、集合技能表里的摘要。

- 通过：本次范围没有用户可见变更，并写明原因。
- 通过：有用户可见变更，且对应的 README 已在同一范围内更新。技能自己的说明和集合 README 按实际改动的表面分别看。
- 失败：有用户可见变更，对应 README 没有改。
- 不适用：仓库没有 README，且本次也没有新增用户可见说明。

### PP-05 差异中的安全问题

只看本次差异新引入的问题，不做漏洞库检索，不收录外部实验室的检测规则。

要看的种类：秘密材料、在改动行里关掉认证或授权、用未清洗的输入拼命令、从意外来源加入依赖。

- 通过：这些种类在本次差异里没有出现。通过不表示代码是安全的。
- 失败：写出路径和种类。不贴出秘密或可直接利用的载荷。

### PP-06 仓库自有的公开表面

仅当仓库里存在对应文件时才检查本次差异碰到的那一块：

- 技能同时有中英文说明时，行为变更要两边一起改，版本号一起动
- 集合 README 里的技能表、安装命令、徽章数量，要和本次差异声称的发布状态一致
- 市场索引里已经列出的技能，版本变更时索引要在同一范围内跟上

- 不适用：仓库没有这些文件，或本次差异没有碰到它们。
- 通过：碰到的表面互相一致。
- 失败：同一范围内中英文行为不一致、徽章或安装命令数量和已发布状态不符、或索引里的版本没有跟上。
- 某技能故意不在某个市场索引里时，缺席是一致的，不因此失败。本清单不要求顺便发布。

### PP-07 第三方许可声明

- 不适用：本次没有引入成段的他人文字。
- 通过：引入的文字在文件内保留了对方的版权行和许可声明。
- 失败：成段复制却没有保留版权行和许可声明。写出路径。

### PP-08 不该入库的文件

用 `git ls-files -ci --exclude-standard` 查看已被跟踪、却又匹配忽略规则的文件。同时看本次范围是否新增日志、临时夹具、对比报告、构建产物、本机痕迹。

本机路径只对照仓库声明的禁止前缀。有 `sync/manifest.sh` 时读取 `SYNC_FORBIDDEN_PATHS`，不把前缀抄进报告以外的技能正文。

- 通过：没有这类文件。
- 失败：写出路径和种类（忽略规则、日志、临时夹具、对比报告、构建产物、本机路径）。

### PP-09 二进制与不可读文件

`git diff --numstat` 里左右都是 `-` 的文件，以及其他无法按文本读取的对象。

- 未读：写出路径，结果固定为「未读，需人工确认」。未读不是通过，挡住自动推送。
- 通过：范围内没有这类文件。
- 通过：报告已经列出路径，用户随后明确说该文件可以推送。说明里写「人工确认」。没有这句之前保持未读。
