# 公开推送检查

这只技能在把提交推到公开远端之前，对即将推送的范围跑一份固定清单。清单通过只表示这些项过了，不是对仓库的安全认证。

本技能版本是 `1.0.1`。它留在仓库里，供本仓库维护使用。frontmatter 已标 `metadata.internal: true`：默认不进入 skills.sh CLI 发现与批量安装；站点列表可能延迟更新。不发布到 SkillHub、DSH、ClawHub 或 npm。知情安装（例如显式 `--skill` 或 `INSTALL_INTERNAL_SKILLS=1`）仍可能装上。

终端里直接执行的 `git push` 不会调用本技能。本技能只在代理被要求推送或做推送前检查时运行。

## 铁律

1. **先检查，再推送。** 同一句话里要求推送时，先出清单。有失败、未确认或未读，就不推。
2. **不改写历史。** 不强制推送，不跳过钩子，不改 git 配置。已经在远端的秘密记为已公开，不用新提交假装消除，也不改写历史。
3. **秘密只报路径和类型。** 不把密钥、令牌、口令或私钥正文写进报告，也不写进后续提交说明。
4. **作者只能是允许名单中的人。** 作者、提交者，以及提交说明里的共同作者和签名者，都必须是这份名单里的同一个人。身份字段里出现代理、机器人或模型就失败；这种身份写进允许名单也仍然失败。不猜测公司域名，不把任何邮箱写进本技能。名单缺失时，这一项失败，并只问一次名单放在哪里。
5. **推送不是上架。** 本清单不要求每次 git push 都发布到某个市场。

## 何时使用

- 「推送到公开仓库」「push 前检查」「帮我 push」「before you push」
- 同一句话里要求提交并推送到公开远端

## 何时不用

- 只提交、不推送
- 远端已经确认不是公开仓库。这时跳过公开清单并说明，不把跳过写成通过

## 流程

1. **确定远端。** 用户点了名就用那个远端，否则用 `origin`。用 `git remote get-url` 取出地址。GitHub 仓库用 `gh repo view <owner/repo> --json visibility,isPrivate` 判断公开性。查不到、命令失败，或主机不是 GitHub 且没有同等的公开性证据时，公开性记为未确认，停止，不推送。
2. **确定范围。** 有上游时用 `上游..HEAD`。没有上游但存在 `远端/当前分支` 时用它。新分支用相对远端默认分支、本次会送出的提交，并写明实际使用的范围。工作区里尚未提交的改动不在推送范围内；同一句话要求先提交再推送时，把暂存区和工作区并入同一次检查，再创建提交。本技能不主动创建提交。
3. **按清单判定。** 先读 [`references/checklist.md`](references/checklist.md)。九项都要有结果。仓库没有对应文件的项记为不适用。
4. **出报告。** 用清单里的报告格式。结果只使用：通过、失败、不适用、未读、跳过、未确认。
5. **再决定是否推送。** 用户没有要求推送时，停在报告。用户要求推送，且每一项都是通过或不适用时，执行不带 `--force`、不带 `--no-verify`、不写入 git 配置的推送，例如 `git push <remote> HEAD:<branch>`。远端非公开时，公开清单记为跳过；用户要求推送就可以推。其余任何一项不是通过或不适用，就停止。

仓库若有 `.githooks/pre-commit`，那是另一道提交时的机械检查，不代替本清单。本技能不启用钩子，也不修改 git 配置。

## 不做的事

- 不把清单通过说成安全认证
- 不做漏洞库检索，不收录科恩实验室或云鼎实验室的检测规则
- 不评审本次差异以外的代码是否正确
- 不要求顺便发布到 SkillHub、DSH、ClawHub 或其他市场
- 不改写历史，不强制推送
